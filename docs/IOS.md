# iOS app

The iOS app is a native shell (Capacitor 8) around the live web app. Pages are rendered by the server, so the app loads `APP_ORIGIN`; `native-shell/` is only the offline page. What the app adds:

- **Push notifications** (APNs): new calls, calls about you, "picks close soon", time to settle, results to check, votes, results, called-off calls, reviews. Tapping one opens the right page.
- **Home-screen and lock-screen widget** (`ios/App/WhollWidget`): how many calls need you, how many are open, and when the next one closes. Counts only, nothing personal.
- **Native share sheet** for result links.
- **Universal links:** sign-in links, invites, groups and shared results open in the app when it's installed.

Every push to `ios/**` builds the app and widget for the simulator on GitHub's Macs (`.github/workflows/ios.yml`), unsigned, so native code is checked without a Mac.

## How it fits together

| Piece | Where |
|---|---|
| Push token → server | `src/app/NativeBridge.tsx` → `registerDeviceAction` → `devices` table. Each phone belongs to the session that registered it, so signing out stops its pushes. |
| Sending pushes | Outbox channel `push` (`src/server/notify.ts` → `src/server/delivery.ts` → `src/server/apns.ts`). Lease, retries, stale checks and expiry work like email. Dead tokens are disabled. Sandbox/production is learned per phone. |
| Widget data | The app gets a read-only widget token (`widgetTokenAction`) and stores it in the App Group through the `WidgetBridge` plugin (`ios/App/App/WidgetBridgePlugin.swift`). The widget calls `GET /api/widget`. "Sign out everywhere" and account deletion revoke it. |
| Universal links | `/.well-known/apple-app-site-association` (served by `src/app/api/aasa/route.ts`) and the `applinks:` entitlement. |
| Xcode project | Generated by `npx cap add ios`, then `node scripts/ios-setup.mjs` adds the app's Swift files, entitlements and the widget target. Both outputs are committed; CI checks the script changes nothing. |

## One-time Apple setup

1. Join the Apple Developer Program.
2. Create an App ID `app.wholl.ios` (or your own) with **Push Notifications**, **App Groups** and **Associated Domains**. Create the App Group `group.app.wholl.ios`.
3. Create an App ID `app.wholl.ios.widget` with the same App Group.
4. Create an **APNs key** (Keys → +, Apple Push Notifications service). Download the `.p8` once and note its Key ID and your Team ID.

If you use your own bundle ID or domain, rerun the setup script and commit the project file:

```sh
IOS_BUNDLE_ID=com.you.wholl APP_ORIGIN=https://your.domain node scripts/ios-setup.mjs
```

## Server settings

| Variable | Value |
|---|---|
| `APNS_TEAM_ID` | Your 10-character Team ID (also used for universal links) |
| `APNS_KEY_ID` | The APNs key's ID |
| `APNS_KEY` | The full contents of the `.p8` file (newlines may be written as `\n`) |
| `IOS_BUNDLE_ID` | `app.wholl.ios` |

Without the APNs settings, development prints pushes to the console instead.

## Build and run (on a Mac with Xcode)

```sh
npm ci
APP_ORIGIN=https://your.domain npx cap sync ios
npx cap open ios
```

In Xcode, pick your team under Signing & Capabilities for both targets, choose a simulator or your phone, and run.

To point the app at your computer while developing, use `APP_ORIGIN=http://<your-mac-ip>:3000` for `cap sync`. The simulator can also use `http://localhost:3000`.

## Releasing

- App Store Connect requires a recent Xcode/iOS SDK. CI currently builds with the runner's default Xcode (16.4 on `macos-15`). Before uploading to TestFlight, build with the newest Xcode (for example on a `macos-26` runner).
- Set `aps-environment` to `production` in `ios/App/App/App.entitlements` for App Store builds (Xcode does this automatically when archiving with a distribution profile).
- The App Store questionnaire: points are free, can't be bought or cashed out, and there are no prizes. See the product rules in `AGENTS.md`.
